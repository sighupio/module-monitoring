# Monitoring Module Release v4.3.1

Welcome to the latest release of the `monitoring` core module of the [`SIGHUP Distribution`](https://github.com/sighupio/distribution), maintained by team SIGHUP by ReeVo.

This is a patch release that updates `kube-state-metrics` to `v2.19.1`, fixing a crash caused by CronJobs with schedules that `kube-state-metrics` cannot parse.

## Bug Fixes 🐞

### kube-state-metrics

Updated `kube-state-metrics` from `v2.19.0` to `v2.19.1`, which fixes the following upstream issues:

- [[kubernetes/kube-state-metrics#2988](https://github.com/kubernetes/kube-state-metrics/issues/2988)] `kube-state-metrics` no longer crashes when a CronJob has a schedule that the Kubernetes CronJob controller accepts but `kube-state-metrics` cannot parse (for example `*/60 * * * *`). In `v2.19.0` a single such CronJob put the whole pod in `CrashLoopBackOff`, stopping all `kube-state-metrics` metrics for the cluster. The CronJob is now logged and skipped instead ([kubernetes/kube-state-metrics#2978](https://github.com/kubernetes/kube-state-metrics/pull/2978)).
- Fixed watch-list bookmarks when sharding is enabled ([kubernetes/kube-state-metrics#2974](https://github.com/kubernetes/kube-state-metrics/pull/2974)).
- Updated the Go toolchain and dependencies to address several CVEs, including CVE-2026-42504 ([kubernetes/kube-state-metrics#2981](https://github.com/kubernetes/kube-state-metrics/pull/2981), [kubernetes/kube-state-metrics#2982](https://github.com/kubernetes/kube-state-metrics/pull/2982)).

## Update Guide 🦮

The furyctl tool now manages Module installations and upgrades. The instructions below are left for reference when using the legacy version of furyctl.

### Process

To upgrade this core module from `v4.3.0` to `v4.3.1`, execute the following:

```bash
kustomize build <your-project-path> | kubectl apply -f - --server-side
```
