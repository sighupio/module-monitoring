# Mimir - maintenance

## Customizations

Before starting the maintenance activities, have into account that the following changes have been applied to what we get from upstream:

- Disabled mimir alertmanager
- Disabled in-tree minio, configured to use our own minio-ha deployment
- Disabled overrides exporter
- Disabled ruler
- Removed Alertmanager and Ruler location blocks from the nginx gateway config (since components are disabled, the gateway would proxy to non-existent services and cause 502 errors)
- Added `manageAlerts: false` to the mimir datasource (`datasources/mimir.yaml`) since ruler is disabled — prevents Grafana from trying to load rules via the Alerting UI
- Disabled rollout operator
- Grafana dashboards have been added manually instead of using the autogenerated configmaps from the chart
- PrometheusRules have been moved to a dedicated file
- Removed Pod Security Policy
- Mimir runs in classic architecture (ingest storage disabled) via `mimir.structuredConfig` in `MAINTENANCE.values.yaml`
- Added `compactor_blocks_retention_period: 720h` and `max_global_series_per_user: 0` via `mimir.structuredConfig` in `MAINTENANCE.values.yaml`
- Enabled Gateway for non-enterprise
- Enabled autoscaling (HPA)
- Changed Grafana Dashboards annotations and labels to make them compatible with SD's monitoring
- Enabled Service Monitor
- Disabled Graphite's aggregation cache
- Disabled Graphite's metric name cache
- Enabled continuous-test
- Removed Smoke Test

## Upgrading

To update the Mimir package, follow these steps.

> [!IMPORTANT]
> The following commands assume your PWD is `fury-kubernetes-monitoring/katalog/mimir`.

1. Get the latest available chart versions:
   ```bash
   mise run chart-version
   ```

2. Update the `kubeVersionOverride` value in `MAINTENANCE.values.yaml` to match the `kubeVersion` constraint required by the chart version you are about to upgrade to (see the `Chart.yaml` of the target chart version). The upgrade task will fail at `helm lint` if the chart's `kubeVersion` constraint is not satisfied.

3. Run the upgrade script, specifying the desired chart version:
   ```bash
   mise run upgrade <chart_version>
   # Example
   mise run upgrade 6.2.0
   ```
   The script will pull the specified chart version, update the Helm repo, bump image tags in `MAINTENANCE.values.yaml`, render the chart templates, copy dashboards, and build Prometheus rules.

   > Mimir Distributed Helm chart source code is here: <https://github.com/grafana/mimir/tree/main/operations/helm/charts/mimir-distributed>

4. Open the `MAINTENANCE.values.yaml`, verify that the values still apply and are aligned with the new version of the chart. Check for deprecated parameters in the chart's CHANGELOG.

5. Check differences between the newly generated `deploy.yaml` and the previous version, and apply any manual adjustments. Note that we don't port the smoke-test job.

   > [!NOTE]
   > The `config/mimir.yaml` file is regenerated by the `upgrade` task from the chart's rendered config (`useExternalConfig=false` applies `mimir.structuredConfig`). To change the config, edit `mimir.structuredConfig` in `MAINTENANCE.values.yaml` and re-run the upgrade task. Review the chart's `mimir.config` template and the Mimir CHANGELOG for any configuration changes between versions.

6. Review the dashboards copied by the script in the `dashboards/` directory. The script excludes dashboards for disabled components (alertmanager, ruler, rollout-operator, overrides, rollout-progress). Update `dashboards/kustomization.yaml` if any new dashboards should be included or excluded.

7. Check differences between the newly generated `prometheusRules.yaml` and the previous version, and apply any manual adjustments.
